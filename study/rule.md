# study/ の作業ルール

## ファイル

- 日本語の本文は `study/*.md`、英訳は `study/en/*.md` に置く。英訳は日本語と同じ節、同じ表、同じ式を持つ。
- 各ファイルの 1 行目に行き来のリンクを置く。日本語のノートは `[← Back](README.md) | [English](en/ファイル名) | [Japanese](ファイル名)`、英語のノートは `[← Back](README.md) | [English](ファイル名) | [Japanese](../ファイル名)` の形である。

## 並べ方

- 上から順に読めるように並べる。前の節やノートで説明していない言葉は使わない。後の節やノートで定義する言葉を先に使わない。
- 各ノートの先頭に「前提」の表を置く。前のノートのどの言葉を使うかを書く。
- 各ノートの最後に「このリポジトリでの使われ方」の表を置く。README の節と notes/ の節を挙げる。

## 言葉

- 言葉は使う前に定義する。
- 今ある言い方で足りるときは、新しい言葉を作らない。覚える言葉を少なくするためである。何度も使うものだけに名前を付ける。
- 「父」ではなく「親」と書く。
- 1 つの言葉には 1 つの意味だけを持たせる。次の言葉は、それぞれ次の意味だけに使う。
  - 段：関係 $`R`$ の再帰の段（上端、鍵）。
  - 高さ：構造の高さ（領域 $`\{x \mid x \lt \gamma\}`$ の $`\gamma`$）。
  - 次数：行（$`\omega^\omega`$ より小さい順序数）の次数。
  - 跳び：2 つの行の跳び。山の辺には「辺の跳び」と書き、「次数」とは書かない。
- 根の列のラベルは「根のラベル」と書く。「根の添字」とは書かない。

## 中身

- 定義を先に書き、そのあとに小さい例を書く。
- 定理には証明か、証明の概略を付ける。ここで証明しないことは、そう書く。
- 形式化（証明支援系）について書かない。形式化での名前、ファイル、コード、形式化についての注意を書かない。定理や対象には、数学の名前か番号（「性質 2」「§8 の補題 1」など）を付ける。
- 構造は $`(A; P_1, \ldots, P_k)`$ の形で書く。この書き方は、最初に使う [03](03-sigma1-elementary.md) §1 で説明する。
- 例の値は Python で計算するか、手で定義をたどって求める。証明支援系では計算しない。どちらで求めたかを書く。計算機の 1 回の実行は 60 秒以内にする。
- 数値の試験は証明ではない。試験の結果を書くときは、範囲（列の長さ、値の上限、展開の回数）を書く。

## 文

- 短い文で書く。1 つの文に 1 つのことを書く。
- 比喩を使わない。文字どおりの言葉で書く。
- 数式で書けることは数式で書く。

## 数式（GitHub で表示するため）

- 文中の数式は `` $`...`$ `` の形で書く。
- 別行の数式は ```` ```math ```` の囲みで書く。
- 文中の数式では、不等号を `\lt`、`\gt` と書く。
- 行の区切りは `\cr` を使う。バックスラッシュを 2 つ並べる書き方は使わない。
- 箇条書きの中では、囲みの数式を使わない。文中の数式だけを使う。
- 表のセルの中の数式に `|` を書かない。`\mid` を使う。

## ほかのプロジェクトの参照

- ほかのプロジェクトは、公開されている GitHub の URL で参照する。ローカルのパスは書かない。
- 1-Y 版の study（[koteitan/1y-wo-por の study/](https://github.com/koteitan/1y-wo-por/tree/main/study)）と weak-magma ω-Y 版の study（[koteitan/wmwy-wo-por の study/](https://github.com/koteitan/wmwy-wo-por/tree/main/study)）と同じ数学は、同じ順で書く。文は写して直してよい。定義と記号は、このリポジトリのものに合わせる。
